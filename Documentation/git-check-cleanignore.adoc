git-check-cleanignore(1)
========================

NAME
----
git-check-cleanignore - Debug gitcleanignore / clean exclude files

SYNOPSIS
--------
[verse]
'git check-cleanignore' [<options>] <pathname>...
'git check-cleanignore' [<options>] --stdin

DESCRIPTION
-----------

For each pathname given via the command-line or from a file via
`--stdin`, check whether the file would be protected from removal by
linkgit:git-clean[1] according to the cleanignore rules and output the
path if it is protected.

By default, tracked files are not shown in the output, as they are not
subject to cleanignore rules anyway.

See linkgit:gitcleanignore[5] for details about cleanignore file format
and how patterns are matched.

OPTIONS
-------
-q, --quiet::
	Don't output anything, just set exit status.  This is only
	valid with a single pathname.

-v, --verbose::
	Instead of printing the paths that are protected, for each path
	that matches a pattern, print the pattern together with the path.
	The format is: '<source> <COLON> <linenum> <COLON> <pattern> <TAB> <path>'

--stdin::
	Read pathnames from the standard input, one per line,
	instead of from the command-line.

-z::
	The output format is modified to be machine-parsable (see
	below).  If `--stdin` is also given, input paths are separated
	with a NUL character instead of a linefeed character.

-n, --non-matching::
	Show given paths which don't match any pattern.  This only
	makes sense when `--verbose` is enabled, otherwise it would
	not be possible to distinguish between paths which match a
	pattern and those which don't.

--no-index::
	Don't look in the index when undertaking the checks. This can
	be used for debugging why a path is not protected as expected,
	e.g., when it was recently added.

OUTPUT
------

By default, any of the given pathnames which match a cleanignore
pattern will be output, one per line.  If no pattern matches a given
path, nothing will be output for that path; this means that path will
not be protected from cleaning.

If `--verbose` is specified, the output is a series of lines of the form:

	<source> <COLON> <linenum> <COLON> <pattern> <TAB> <pathname>

<pathname> is the path of a file being queried, <pattern> is the
matching pattern, <source> is the pattern's source file, and <linenum>
is the line number of the pattern within that source.  If the pattern
contained a `!` prefix or `/` suffix, it will be preserved in the
output.  <source> will be an absolute path when referring to the file
configured by `core.cleanExcludesFile`, or relative to the repository
root when referring to `.gitcleanignore` or `.git/info/cleanignore`.

If `-z` is specified, the pathnames in the output are delimited by the
null character; if `--verbose` is also specified then null characters
are also used instead of colons and tabs:

	<source> <NULL> <linenum> <NULL> <pattern> <NULL> <pathname> <NULL>

If `-n` or `--non-matching` are specified, non-matching pathnames will
also be output, in which case all fields in each output record except
for <pathname> will be empty.  This can be useful when running
non-interactively, so that files can be incrementally streamed to
STDIN of a long-running check-cleanignore process, and for each of
these files, STDOUT will indicate whether that file matched a pattern
or not.  (Without this option, it would be impossible to tell whether
the absence of output for a given file meant that it didn't match any
pattern, or that the output hadn't been generated yet.)

Buffering happens as documented under the `GIT_FLUSH` option in
linkgit:git[1].  The caller is responsible for avoiding deadlocks
caused by overfilling an input buffer or reading from an empty output
buffer.

EXIT STATUS
-----------

0::
	One or more of the provided paths is protected.

1::
	None of the provided paths are protected.

128::
	A fatal error was encountered.
